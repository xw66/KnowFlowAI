# 证据问答增量

新增 `POST /api/knowledge-bases/{id}/answers`，请求 question、可选 topK（默认 4，上限 8）、mode（默认 HYBRID）与 rerank。复用现有权限检索；无候选时直接返回 INSUFFICIENT_EVIDENCE，不调用聊天模型。

新增 chat 包的配置、服务与控制器，不增加数据库表；会话持久化在第 10 项实施。Spring AI 2.0.1 的 OpenAiChatModel 连接已配置的百炼 qwen3.8-flash，JSON 输出、关闭思考、默认最多 512 输出 Token、请求超时 20 秒、不自动重试。SSE 与更完整的超时 / Fallback 已接入，默认仍关闭重试和备用模型。

服务端按检索顺序生成 C1、C2 等编号。系统指令与包含问题、原文的 JSON 用户消息分离，文档只是不可执行的数据。模型返回 answer 及 citations（id、quote）；只接受候选内编号和原文的连续摘录，正文中的 [C数字] 集合须与引用一致。没有引用时丢弃生成内容，使用固定的无法确认说明；未知编号、捏造摘录、非法 JSON、截断输出返回错误。

调用后在短事务内重新验证全部输入证据的当前权限、READY 状态、激活版本和原文内容。任一输入片段失效则不返回生成回答，避免只删除引用而泄露已经生成的正文。引用中的文档名、分块 ID、页码或段落号均由服务端读取。

引用校验保证来源可核验，不等同于自动证明每项陈述的语义正确性；证据支持程度和对抗性文档仍需第 18 项真实评测。返回的聊天 usage 仅采用服务实际提供的数据，缺失为 null；持久化统计和成本估算后续实现。
