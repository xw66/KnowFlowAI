# 版本价格与成本估算

V17 新增 model_price 价格目录，并在 model_call 保存调用开始时的价格快照。目录按服务地址、模型和调用类型匹配，查询改写使用聊天价格。只去除服务地址末尾斜杠，不把其他地域、代理或同名兼容服务当作北京百炼。

初始目录使用 [价格核对记录](model-pricing-research.md) 中的北京在线公开标价，币种限定 CNY。目录只通过迁移追加新版本，不提供价格写接口；选取核对日期不晚于当天的最新版本，同日按目录 id 排序。核对日期不是官方调价生效日。版本、单价、范围和来源复制到调用记录，后续目录更新不改变已开始调用的估算依据。旧调用不追溯填充价格。

终态写入与估算在同一条 MySQL UPDATE 中完成，沿用 RUNNING 条件保护。使用 DECIMAL 运算和 12 位小数存储，不使用浮点金额：

- CHAT / REWRITE：输入量 × 输入单价 + 输出量 × 输出单价，除以一百万；两种用量均须已知且输入量在定价范围内。
- EMBEDDING：输入量 × 输入单价 / 一百万，输出价格为零。
- RERANK：总量 × 总量单价 / 一百万。百炼文本排序仅对输入收费，API 总量按该计费口径估算，原始输入/输出字段仍为 NULL。

价格未匹配、必需用量缺失、超过已知价格范围，或返回模型名与请求模型名不同，estimated_cost 均为 NULL。未返回模型名时按匹配的请求模型估算。失败但保留可信用量的调用也估算，不能抹掉已经发生的消耗；明确的零用量可以得到零估算。无法写回的记录保持 RUNNING / 未知费用。

管理员列表返回价格版本、币种、单价、范围、核对日期、来源和 estimatedCost；汇总提供 estimatedCalls、unknownCostCalls、estimatedCostCny。合计仅覆盖可估算调用，没有可估算记录时为 NULL。它是公开标价估算，不是实际账单，不预扣免费额度、缓存优惠或其他折扣。

验证使用真实 MySQL，覆盖四类计费、极小金额精度、失败调用、未知费用、地域和模型不匹配、定价范围、未来版本、快照隔离与迟到回调。没有为验证费用公式调用真实模型。

本增量不包含预算预留或额度拦截。新的付费联调仍暂停，下一步在请求前加入累计 20 元预算控制，之后再做真实问答和 SSE 验证。
