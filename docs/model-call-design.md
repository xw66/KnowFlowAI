# 模型调用记账

当前覆盖同步回答和 SSE 回答的聊天主模型、重试、备用模型尝试，以及查询改写。每次尝试单独保存到 V15 的 `model_call`，同一次聊天使用相同 invocation_id 和递增 attempt_number，并关联 chat_message。不保存提示词、回答正文、密钥或服务地址。

Embedding 查询与 Worker 分批入库也写入同一账本：call_type=EMBEDDING，route 分别为 QUERY / INDEX。V16 增加 task_id，INDEX 调用关联 document_task，查询调用为空；管理员列表返回 taskId。每批和每次重试独立记录，不能把同一任务的多次调用合并成一次。实际请求仍使用原模型配置和零 SDK 重试，不跨模型切换。

两处调用共用 EmbeddingCalls，通过 Spring AI 的 embedForResponse 保留原生 usage 和模型名，向量内容不写入账本。已知 Embedding usage 的输出 Token 为 0；失败或缺少可确认 usage 时保留未知。模型返回后即记录调用完成；维度错误、Qdrant 写入失败或任务提交失败仍可能已发生模型费用，不将其删除或改为零。记账不可用时查询返回不可用、Worker 按既有任务重试处理，两处都不发送新的模型请求。

`call_type=CHAT` 表示回答，`REWRITE` 表示改写；同一消息可以分别产生改写和回答记录。未请求改写或没有有效历史时不产生改写记录。改写 HTTP 完成但内容不合法时仍记录 COMPLETED 和实际 usage，业务状态独立记录 FALLBACK；调用失败记 FAILED。改写开始记账失败时不发送改写请求，仍按原逻辑退回原问题。改写同步写入终态，失败保留 RUNNING，不自动重试。原有 128 输出 Token、3 秒模型超时和零重试配置不变。

调用前通过独立事务插入 RUNNING；插入失败返回 503，不发送模型请求。业务事务回滚不撤销已经发生的调用记录。COMPLETED 表示模型调用完成，回答仍可能因引用校验失败而被拒绝，不能以调用状态替代消息状态。

记录请求模型、实际响应模型、是否流式、最终状态、异常类型、耗时及原生 usage。流式 usage 按累计值覆盖，不按分片相加。缺少原生 usage 时 Token 保持 NULL、usage_known=false；失败也可能产生费用，未知不等于免费。耗时从开始记录提交后计到尝试终止，不包括检索、开始记账及终态持久化。

聊天回答的结束写入在现有 boundedElastic 调度器异步执行，避免阻塞模型回调和超时线程；改写与 Embedding 在同步调用线程写回。通过 RUNNING 条件更新阻止迟到回调覆盖终态。查询可能短暂看到 RUNNING；数据库不可用或进程中断时记录保持未决并输出结构化错误，不触发模型重试。后续对账必须保留不确定性，不能把未决记录直接改成零消耗成功。

管理员接口使用现有 ADMIN 授权，普通用户无权读取；响应 no-store：

- `GET /api/admin/model-calls?afterId=0&limit=50`：按 id 分页，最多 100 条。
- `GET /api/admin/model-calls/summary?from=2026-09-04T00:00:00Z&to=2026-09-05T00:00:00Z`：按 UTC 开始时间、左闭右开统计，默认最近 24 小时，最大 31 天。

汇总按尝试计数，分别返回终态、未决及已知/未知 usage 的数量；Token 合计仅包含已知值，没有已知数据时为 NULL。平均耗时仅覆盖已结束且成功写回的尝试。

Spring AI 2.0.1 会将缺失的流式 usage 合成为全零对象。账本与 SSE 共用校验，将流式全零值保守视为未知；该版本无法区分真实全零和合成全零。同步调用有原生 usage 时仍可记录零值。

本增量尚不覆盖 Rerank 调用账本，尚无价格版本或成本估算。不能用该汇总代表全部模型消耗。付费联调继续等待完整费用和预算控制。

验证使用真实 MySQL 与本地模型 HTTP 协议替身：独立事务、终态不能覆盖、数据库故障、管理员权限及撤权、汇总与分页参数、重试分组、累计/缺失 usage、取消，以及同步/SSE 消息关联。测试替身不提供模型效果或真实费用结论。
