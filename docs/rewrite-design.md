# 查询改写增量

新增 QueryRewriteService，复用现有 Spring AI ChatModel。答案请求显式 rewrite=true 时，取同一用户、同一知识库、同一会话最近一轮完整且来源仍有效的问答，生成独立检索问题。首次提问、不启用开关或历史无效时不调用改写模型。历史正文最多 2000 字符，当前问题仍受原有 2000 字符限制；改写最多 128 输出 Token、3 秒超时、无重试、关闭思考。模型只返回 query，不能指定知识库、过滤条件或工具。

V12 在 chat_message 增加原问题、实际检索问题、改写状态、改写实际模型与 usage，以及被使用的历史消息 ID。历史依赖只允许指向更早的同会话消息；递归检查历史来源，任意来源失效则隐藏衍生答案及改写问题。同步返回前、SSE 每次输出前、完成保存和历史读取均检查依赖。

改写格式错误、空白、超长、截断或模型异常时回退原问题；不改变当前知识库范围。状态为 NOT_REQUESTED / NO_CONTEXT / UNCHANGED / APPLIED / FALLBACK。改写失败不让整个问答失败，权限和数据库故障仍拒绝放行。

对照样例通过本地协议替身验证“报销需要什么材料 → 这个流程找谁审批”改写为独立的报销审批问题后，BM25 可以检索对应材料；该样例验证数据流及对照机制，不代表真实模型的质量收益。真实改写收益在真实模型评测中单独报告。
