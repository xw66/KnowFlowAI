# Redis 请求幂等协调

默认 IDEMPOTENCY_ENABLED=true，IDEMPOTENCY_LEASE=PT30S，租约允许 1 秒至 5 分钟。沿用 StringRedisTemplate 与 Redis Lua，不引入锁框架，不新增数据库表。

上传和重新索引先检查当前知识库编辑权限，再以 SET NX PX 取得短期协调锁。上传作用域为「操作 + 知识库 + 用户 + Idempotency-Key」，重新索引额外包含文档 ID。不同用户、知识库和操作不会互相占用额度。锁在本地文件保存之前取得，但不阻止 Servlet 接收 multipart 请求体。

同一作用域已有请求处理时返回 409，请稍后使用原键重试。持锁请求完成后，重复上传仍通过文件名和 SHA-256 验证，返回原任务；同键不同文件继续返回 409。重新索引重试返回原任务，不额外递增版本。当前权限每次重新检查，幂等键不能绕过撤权。

每次获取锁使用随机令牌；释放用 Lua 比较令牌后删除，旧请求不能删除过期后新请求取得的锁。普通调用在数据库事务结束后释放；加入外层事务时延迟到 afterCompletion，提交和回滚都释放。业务异常同样进入释放流程。

不续租，也不声称仅靠 Redis 达到恰好一次。慢请求超过租约、Redis 故障或 SET 结果未知时，可能有多个请求进入数据库：原知识库/文档行锁、唯一约束、同事务 document_task 与 Outbox 写入仍负责最终去重。协调锁与 Worker 的任务执行租约相互独立。

释放失败不能把已提交的成功响应改成失败，残留锁依赖 TTL 清理；期间原键重试可能返回 409。SET 结果未知也可能留下短期锁。Redis 不缓存任务响应或文件，不作为成功状态的事实来源。日志只记录异常类型，不记录密钥或幂等键。

与限流故障策略区分：注册/登录/搜索/问答限流故障返回 503；已有登录用户的上传/重新索引在 Redis 协调故障时继续使用数据库约束。关闭全部 Redis 功能时还需关闭缓存、限流及 Redis 健康检查。

DocumentTests 使用真实 Redis、MySQL、HTTP multipart 和临时文件目录，验证处理中的请求拒绝、串行重放、作用域、旧持有者误释放、外层事务提交/回滚后释放、超时上传去重、Redis 获取/释放故障及并发重新索引。并发请求可以返回 202 或暂时的 409；完成后用原键重试必须返回同一任务。

协议依据：[Redis 单实例锁的随机令牌与安全释放](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)。
