# 预算控制方案（待实现）

目标：新增真实联调与评测累计不超过 20 元。当前只有费用估算，预算拦截尚未实现，继续暂停真实调用。

## 已核对的边界

2026-09-04 核对官方接口文档，以下仅针对当前三个北京百炼模型和文本调用：

| 调用 | 上界依据 | 按当前标价计算的保守单次预留 |
|---|---|---:|
| CHAT / REWRITE | 输入按 1,000,000 Token，输出按 131,072 + 最大思维链 262,144 Token 保守合计 | 1.8616832 元 |
| EMBEDDING | text-embedding-v4 每批最多 10 条，每条 8,192 Token | 0.04096 元 |
| RERANK | 应用最多 50 个候选；Query 与每个 Document 各按 4,000 Token，按重复 Query 的公式保守计算 400,000 Token | 0.32 元 |

上述金额是本项目按公开限制和标价计算的预留上界，不是实际消耗。Rerank 服务还有更低的总请求限制，保守预留不代表能发送到这个长度。聊天预留不利用当前关闭思考和 512 输出 Token 的更低上限，避免将请求选项误当成服务完整计费边界。正式启用前再次核对价格及限制，并绑定支持的模型、地域与版本；无可信上界时拒绝付费调用。

来源：[Qwen3.8-Flash 限制](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)、[Embedding 兼容接口限制](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api)、[Rerank 输入与计费长度公式](https://help.aliyun.com/zh/model-studio/text-rerank-api)、[价格核对记录](model-pricing-research.md)。

核对中发现 Worker 原来的 16 条批次超过 text-embedding-v4 的 10 条上限，已改为 10 条；模型测试替身现在同样拒绝超限请求，防止回归。

## 下一增量的实现约束

- 复用 MySQL 独立事务：锁定唯一预算行，再创建调用记录和预留；API、Worker、重试、备用模型共享额度。
- 可用额度 = 20 元 − 已结算标价金额 − 仍被预留的金额。额度不足、价格或上界未知、数据库不可用时，在发送 HTTP 前拒绝。
- 每次尝试单独预留。已知费用且未超过预留时，同一事务结算并释放差额；使用现有终态条件更新，重复回调不重复扣款或退款。
- 超时、断开、未知 usage、写回失败或进程中断时不自动释放预留。若费用超过上界，冻结后续调用并报告，不掩盖异常。
- 不按日重置，不随进程重启重置，不推算历史缺失费用；提供管理员只读预算状态，不提供远程增加额度接口。
- 正常启用预算保护，自动测试通过显式测试配置隔离真实费用。上线前验证并发竞争、边界额度、事务回滚、重复终态、未知用量、重启保留与四类调用的请求前拦截。

完成并验证预算控制后，再恢复小规模真实问答和 SSE 联调；请求追踪、索引对账、完整 Compose、评测和压测仍在后续主线中。
