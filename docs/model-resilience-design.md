# 模型韧性增量

新增 ChatCalls，共用同步与流式调用的有限重试和备用聊天模型；不增加表或依赖。主模型 SDK 重试固定为 0，应用层 CHAT_RETRIES 默认为 0、最多 2。备用模型显式配置并启用，最多调用一次；未启用不改变已有费用行为。Embedding 保持原模型空间，查询改写仍单次调用失败回退原问题。

连接期限默认 5 秒，聊天调用总期限默认 30 秒；流式首正文期限及输出间隔期限默认各 8 秒。期限覆盖重试等待与模型切换，重试退避从 200 ms 开始。每次调用复制对应模型默认选项，保留密钥、Token 上限、关闭思考及响应格式。底层请求期限不超过本轮剩余总期限。

仅连接 / I/O 错误、超时、408、429、5xx 可重试或切换。401、403、400、引用验证失败和截断不重试。流中出现正文或结束标记后不切换模型、不重新生成；取消订阅同时取消上游。最终答案、历史及 usage 使用真正返回结果的模型信息。

验证使用真实 Spring AI 客户端与本地 HTTP 主备模型服务，检查请求次数、主备顺序、Token / 思考选项、首正文 / 空闲 / 总期限，以及正文后失败和取消不重试；完整回归继续使用真实 MySQL、Kafka、Qdrant。没有真实模型性能或效果结论。

HTTP 传输使用 Spring AI 自带客户端定制入口，设置原生连接及请求超时；每次调用同时限制为剩余总期限，不依赖只停止等待而放任网络请求继续。异步 SDK 的 CompletionException / ExecutionException 会先解包，再按同一规则判断错误。默认 SDK 重试行为参考 [官方 Java SDK 网络选项](https://github.com/openai/openai-java#network-options)，应用显式关闭该默认行为。
